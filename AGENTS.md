# AGENTS.md

Guidance for AI coding agents (and humans) working in this repository.

## What this project is

Emplyo — an employee management web application (ASP.NET Core MVC, .NET 10,
EF Core 10, SQL Server, ASP.NET Core Identity). Modular monolith with Clean
Architecture layering. See the root `README.md` for features and setup.

## Commands

```bash
dotnet build                                            # build (must be 0 warnings)
dotnet test tests/Emplyo.UnitTests                      # unit tests
dotnet test tests/Emplyo.IntegrationTests              # needs SQL Server on localhost:1433
dotnet test                                             # everything
./scripts/dev.sh                                        # ensure SQL Server container, run the app
dotnet run --project src/Emplyo.Web -- migrate          # apply DB migrations (explicit, never automatic)
dotnet ef migrations add <Name> --project src/Emplyo.Infrastructure \
  --startup-project src/Emplyo.Web --output-dir Persistence/Migrations
```

Integration tests run against a dedicated **`Emplyo_Test`** database (derived
from User Secrets `DefaultConnection`, override with `EMPLYO_TEST_CONNECTION`).
It is migrated and seeded but **never reset** — write tests that tolerate data
from previous runs.

## Hard rules

- Dependency direction only: `Web → Infrastructure → Application → Domain`. Never reversed, never skipped.
- `Emplyo.Domain` must not reference EF Core or ASP.NET Core.
- No business logic in controllers or views; controllers stay thin.
- Never add automatic migrations or destructive database operations to startup — database changes go through explicit EF migrations + the `migrate` command.
- Never bind entities directly in forms — use DTOs/view models.
- Roles/policies are constants in `src/Emplyo.Web/Authorization/` — never hardcode role strings.
- Authorization is enforced server-side (policies + resource-based checks); navigation visibility is never the only control.
- Secrets live in User Secrets or environment variables — never in source control.

## Where changes go

- New business module: entity in `Emplyo.Domain/Entities/`, DTOs + interface + service in `Emplyo.Application/<Module>/` (interfaces are colocated in the module's `*Dtos.cs`), DI registration in `Emplyo.Application/DependencyInjection.cs`, controller + views in `Emplyo.Web`, tests as above. Full checklist in `docs/PROJECT-STRUCTURE.md`.
- UI changes: follow the design system in `docs/DESIGN.md`; styles live in `src/Emplyo.Web/wwwroot/css/emplyo.css`.
- Views are `Views/<Controller>/<Action>.cshtml`; shared partials in `Views/Shared/`.

## Generated files — do not edit by hand

- `src/Emplyo.Infrastructure/Persistence/Migrations/*` — generated by `dotnet-ef` (committed as schema history).
- `src/Emplyo.Web/wwwroot/lib/*` — vendored frontend libraries (Bootstrap, jQuery, Chart.js, Inter), intentionally committed for self-hosting.
- `bin/`, `obj/`, `src/Emplyo.Web/App_Data/` — build output and runtime data (ignored).

## Before considering work complete

Run `dotnet build` and both test suites; all must pass with zero warnings.
Update the affected documentation if behavior, structure, or commands change.
